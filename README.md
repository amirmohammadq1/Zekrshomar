# ذکر شمار

برنامه شمارش صلوات و اذکار شیعی، ساخته‌شده با Flutter.

## ساختار پروژه
- `lib/main.dart` — تمام کد و منطق برنامه (یک فایل).
- `pubspec.yaml` — وابستگی‌ها و تنظیمات اسپلش/آیکون.
- `assets/splash.png` و `assets/logo.png` — **باید خودتان اضافه کنید** (فقط همین دو فایل با همین نام در پوشه `assets` قرار بگیرند).
- `android/` — فایل‌های ضروری اندروید/Gradle (این پوشه بخشی جدانشدنی از هر پروژه Flutter است و حذف‌شدنی نیست).
- `.github/workflows/build.yml` — بیلد خودکار APK امضاشده در GitHub Actions.

> نکته درباره‌ی «کم‌کردن فایل‌ها»: کدِ خودِ برنامه (منطق و رابط کاربری) در یک فایل واحد (`lib/main.dart`) نوشته شده. اما پوشه `android/` را نمی‌شود حذف کرد یا در یک فایل خلاصه کرد — این ساختار را خودِ ابزارهای Android/Gradle الزامی می‌کنند تا بتوانند فایل‌ها را پیدا کنند؛ این محدودیتِ Flutter/Android است، نه انتخاب من.

## اجرای محلی (اختیاری)
```
flutter pub get
dart run flutter_native_splash:create
dart run flutter_launcher_icons
flutter run
```

## آموزش امضای برنامه برای مایکت (۰ تا ۱۰۰)

اپلیکیشن‌های اندروید باید با یک «کلید امضا» (keystore) امضا شوند تا در مایکت/گوگل‌پلی قابل انتشار باشند. این کلید هویت شما به‌عنوان توسعه‌دهنده است — **آن را جایی امن نگه دارید و هرگز در گیت‌هاب به‌صورت عمومی قرار ندهید.**

### مرحله ۱: ساخت فایل کلید (keystore)
روی سیستم خودتان (با نصب بودن JDK)، این دستور را اجرا کنید:
```
keytool -genkey -v -keystore zekr-shomar-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias zekrshomar
```
چند سؤال (نام، سازمان، کشور و...) می‌پرسد و در نهایت یک رمز عبور برای keystore و یک رمز عبور برای alias از شما می‌خواهد. این‌ها را جایی یادداشت کنید.

### مرحله ۲: تبدیل فایل کلید به base64
```
base64 -w 0 zekr-shomar-key.jks > keystore_base64.txt
```
(در ویندوز/پاورشل: `certutil -encode zekr-shomar-key.jks keystore_base64.txt`)

### مرحله ۳: افزودن Secret ها به مخزن گیت‌هاب
در گیت‌هاب بروید به: **Settings → Secrets and variables → Actions → New repository secret** و این ۴ مورد را بسازید:

| نام Secret | مقدار |
|---|---|
| `KEYSTORE_BASE64` | محتوای فایل `keystore_base64.txt` |
| `KEYSTORE_PASSWORD` | رمز عبور keystore |
| `KEY_ALIAS` | مقدار alias (مثلاً `zekrshomar`) |
| `KEY_PASSWORD` | رمز عبور alias |

### مرحله ۴: اجرای بیلد
با هر push به شاخه `main` (یا اجرای دستی از تب Actions)، ورک‌فلو به‌صورت خودکار:
1. کلید را از Secret دیکود می‌کند.
2. فایل `android/key.properties` را می‌سازد.
3. APK نهایی را **امضاشده** می‌سازد.
4. آن را به‌عنوان Artifact قابل دانلود در انتهای اجرای Action قرار می‌دهد (بخش Artifacts پایین صفحه‌ی اجرا).

اگر این ۴ Secret را تنظیم نکنید، بیلد باز هم انجام می‌شود ولی APK با کلید موقتِ Debug امضا می‌شود (فقط برای تست مناسب است، نه انتشار در مایکت).

### مرحله ۵: انتشار در مایکت
APK امضاشده را از Artifacts دانلود کرده و در پنل توسعه‌دهندگان مایکت (myket.ir) آپلود کنید. **همیشه از همان keystore برای نسخه‌های بعدی استفاده کنید**؛ در غیر این صورت مایکت/گوگل‌پلی بهروزرسانی را نمی‌پذیرد.
